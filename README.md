# QuickMemo

起動後すぐにメモを取れるメモアプリです（React + Quill、Electron / ブラウザ / iPhone）。メモと正式タスクは Firebase（Authentication / Firestore）で端末間同期します。

## 開発

```bash
npm install
cp .env.example .env.local   # Firebase の設定値を入れる（Git 対象外）
npm run dev                  # ブラウザ
npm run electron:dev         # Electron
npm run build
```

## タスクの入力

タスクはメモにそのまま書きます。チェックボックスの行にタスクを書いて Enter を押すと、画面下に入力欄が出ます。

1. **期限**: `1030`・`10/30`・`10月30日` などで入力（「今日」「明日」のボタンもある）。空欄で Enter なら期限なし
2. **時間**: `30`・`30m`・`1h`・`1.5h`・`1時間30分` などで入力（15分〜2時間のボタンもある）。空欄で Enter なら時間なし
3. **タグ**: 卓球・副業・プライベート・学校から選ぶ（1〜4キー、矢印キー＋Enter、タップ）。前回選んだタグが初期値になる
   - 学校は「生徒名・成績・健康・出欠・連絡先・家庭状況・学校内部資料を含まない一般的な作業です」を確認してから登録する

確定すると行末に「10月30日」「1時間」「卓球」のバッジが付き、その行が正式タスク（AI秘書と同期するデータ）になります。Esc か ✕ でタスクにせず普通の行のまま続けられます。

- 登録した行の文字を編集すると、タスク名・期限・時間をタスクに反映する。チェックを付け外しすると完了・未完了を反映する。触っていない行は反映しない
- 期限の年は、今年の日付が60日より前なら翌年とみなす
- 行とタスクの対応は行属性（`data-task-id`）で持つ。行を消してもタスクは消えない
- ノート一覧の先頭の「タスク」（表示専用の仮想ノート）で、通常ノートのタスク・AI 秘書のタスク・正式タスクに未登録のメモの期限行を1つの画面にまとめて見られる
  - 作成元では分けず、同期の確認が必要 → 期限超過 → 今日が期限 → 今後の期限 → 期限なし → 完了済み（下部で開閉）の順に並べる
  - 各項目に作成元（AI秘書 / 元ノート名 / メモ未紐付け / 元ノートなし）、期限・時間・タグ・状態・同期状態を表示する
  - 正式タスクはチェックで完了・未完了を切り替えられる（右上の一覧と同じ同期キューを通す）。同期の確認が必要なタスクは操作できず、「確認する」から同期の確認を開く
  - 未登録のメモの行は二重のタスク化を避けるため完了操作はせず、選ぶと元のメモを開く
  - notes コレクションには保存しない。削除・名前変更・本文編集はできない。タスクの正本は Firestore の /users/{uid}/tasks だけ
- 右上のリストアイコン（NOTES パネル）で、正式タスクとメモの期限付きの行をまとめて一覧できる
  - Firebase の正式タスクをすべて表示する。AI 秘書が登録したメモに紐づかないタスクは「AI秘書」、元のメモがないタスクは「元ノートなし」、正式タスクに未登録のメモの行は「メモ未紐付け」と表示する
  - 未完了を期限順に表示し、完了済みは「完了済み（N）を表示」で確認できる。期限・時間・タグ・状態・同期待ちを表示する
  - チェックで完了・完了の取り消しができる（同期キュー経由で Firestore と AI 秘書に反映。オフライン中は端末に保存して後で送る）
  - メモに紐づくタスクは、メモの行と二重に出さず1件だけ表示する。選ぶと元のメモを開く。正式タスクのない期限付きの行もメモの行として表示する
  - 競合・保存できない変更があると、パネル上部とタスクに表示し、「確認する」からどちらの内容を使うか選べる
  - メモ名・AI秘書・元ノートなしのチップで絞り込める
- メモ内で見出し行の下のチェック項目がすべて完了すると、確認のあとでそのまとまりを「アーカイブ」メモへ移動する。タスクは移動の前に完了になる
- ほかの端末や AI 秘書と同じタスクを同時に変更した場合は自動で上書きせず、上部に「同期の確認」が出る。押すと、どちらの内容を使うかを選べる

## データと同期

タスクは `/users/{uid}/tasks/{taskId}` に保存します。タスクIDはクライアントで生成したUUIDで、AI-Secretary の SQLite でも同じIDを使います。

- 操作はまず端末内（localStorage の `qm_task_queue_v1_<uid>`）に保存し、Firestore へ冪等に再送します。オフライン中の操作は再接続時（オンライン復帰・30秒ごとの再試行）に送ります
- 更新のたびに `revision` を1つ進めます。他の端末や AI-Secretary が先に更新していた場合は上書きせず、「同期の確認」で「最新の内容」か「この端末の内容」を選んでもらいます
- 初期段階では物理削除はしません
- エラー時のログにはエラーコードだけを出し、タスク本文は出しません

## 学校情報

Firestore は外部クラウドのため、学校の機密情報は保存しません。

- 学校タスクは「生徒名・成績・健康・出欠・連絡先・家庭状況・学校内部資料を含まない一般的な作業です」の確認が必須です（入力欄とセキュリティルールの両方で確認）
- 生徒・成績・出欠などの語を含む学校タスク、氏名・電話番号などの記述は保存前に止めます（AI-Secretary と同じ判定）
- `sensitivity` は `general` / `personal` だけを保存できます

## セキュリティルール

`firestore.rules` の `tasks` 部分で、次の場合だけ書き込みを許可します。

- 本人の UID のパスであること
- 許可されたフィールドだけを持ち、enum・文字数・優先度・推定時間が範囲内であること
- `revision` を1つ進め、`updatedAt` がサーバー時刻であること
- 学校タスクが非機密確認済みであること

物理削除は許可しません。`notes` のルールは変えていません。**本番への反映（`firebase deploy --only firestore:rules`）は、差分を確認して承認を得てから行ってください。**

## テスト

```bash
npm test             # 単体テスト・画面テスト（Vitest + React Testing Library、Fake リポジトリ）
npm run test:rules   # Firestore Emulator でのセキュリティルールと Firestore 実装のテスト
AI_SECRETARY_DIR=/Users/miyamotosoushi/AI-Secretary npm run test:e2e   # AI-Secretary との結合テスト
```

Emulator には Java 21 が必要です。このMacでは `~/.local/jre-21` に入っています。

```bash
export JAVA_HOME="$HOME/.local/jre-21/Contents/Home" PATH="$JAVA_HOME/bin:$PATH"
```

Emulator はプロジェクトID `demo-quickmemo` で動き、本番の Firebase には接続しません。画面を Emulator につないで試すには、次の2つを別のターミナルで実行します。

```bash
npm run emulators      # Firestore と Authentication の Emulator
npm run dev:emulator   # .env.emulator の設定で起動
```
